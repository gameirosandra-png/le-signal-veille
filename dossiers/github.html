GitHub : relire le code proposé par un agent

GitHub présente des agents capables de travailler sur des changements de code et de préparer une pull request. Les journaux de session permettent de suivre les outils utilisés et le travail effectué.

Ce que dit la source

La documentation précise que ces journaux ne remplacent pas votre revue et vos tests. Elle indique aussi que le code produit peut être incorrect ou contenir des vulnérabilités. L’accès aux fonctions dépend de l’offre et des règles de l’organisation.

Lire la documentation officielle ↗

Ce que cela change pour vous

Notre lecture : une proposition de code devient utile lorsqu’on peut vérifier son effet. Relisez le changement en partant du besoin : quel comportement doit être corrigé, quel test le prouve et quels accès ce code utilise-t-il ? Une belle description de pull request ne constitue pas une preuve de fonctionnement.

Un premier pas

À essayer : prenez un petit changement fictif et écrivez un exemple avant/après. Définissez ensuite une vérification qui échouerait avant la correction et réussirait après.

À surveiller

Le périmètre du dépôt, les autorisations de l’agent et la couverture réelle des tests.
